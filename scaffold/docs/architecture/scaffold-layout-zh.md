# 脚手架与工程归属

[English](scaffold-layout.md) | 中文

状态：生效中
最后更新：2026-11-04
适用范围：布局、初始化、文档、回归样例及生成产物

## 决策

保留克隆后初始化。根 README 提供目标工程占位符和明确标注的样例；根 SCAFFOLD 是脚手架自身的 README。脚手架设计、维护历史、初始化、框架样例及维护产物统一归入一级 `scaffold/`。

| 位置 | 归属 |
| --- | --- |
| `README.md`、`docs/`、`scripts/`、`build/` | 目标工程介绍、设计/进度、持续使用的工程工具及工程产物 |
| `SCAFFOLD.md` | 脚手架使用和维护入口 |
| `scaffold/docs/` | 脚手架设计、工具参考、图表、技术文章、vendor 契约及完整维护历史 |
| `scaffold/scripts/` | 初始化和框架回归检查 |
| `scaffold/examples/` | 明确标注为样例的 CI/CD 和编译 fixture |
| `scaffold/build/` | 被忽略的脚手架文档导出和维护产物 |

Agent 自动发现文件、hooks、workflows、可复用规则/Skills 及持续工程检查保留标准根路径。共用工具通过明确根目录处理两类内容，不复制实现，也不为旧路径增加包装脚本。

## 迁移与初始化

- 保留已有本地改动，完整迁移脚手架进度；根工程进度只提供明确标注的条目模板，不继承维护历史。
- 仅位置变化时保留图源、HTML、PNG 字节；修正链接并验证引用，不声称对未变产物进行了新的目视审阅。
- 工程决策与契约保留在 `docs/`；Archify vendor 固定契约迁至 `scaffold/docs/contracts/`。
- 初始化只处理 `scaffold/project-files.json` 明确列出的文件，写入前验证全部路径；排除脚手架内容和 SCAFFOLD，保留参考文档的示例变量拼写。
- 仅在 `package.json` 的名称仍为 `__PROJECT_SLUG__` 时运行布局初始化回归；已初始化工程明确跳过此维护检查，正常质量门禁继续运行，工程名称、文档和带日期进度可独立演进。文档中的示例占位符不会触发维护模式。
- 工程源码扩展名统计排除整个 `scaffold/`，包括参考 HTML 和维护执行器。
- 分别索引和维护 `docs/`、`scaffold/docs/` 的中文配对；Agent/贡献指南继续仅英文。
- 工程文档导出到 `build/portable-docs/`，脚手架文档导出到 `scaffold/build/portable-docs/`，保留路径、符号链接和内容验证。已有忽略的脚手架导出完整迁移，在重新生成前视为历史产物。

## 验收

运行已配置质量、workflow 检查/样例和图表检查。在临时副本初始化：工程值替换成功，脚手架字节不变，可选预览默认值及 CI/CD 延期记录可用，副本通过质量门禁。添加工程进度并定制 README 后再运行布局门禁，必须明确跳过维护回归，且不改写工程文件。覆盖源码探针归属、缺少译本、跨范围导出、非法初始化路径及失败传播；移除范围隔离后，相同反例必须失败。

本次不新增依赖、第三方服务、用户数据收集，也不引入新的生成器或包架构。
