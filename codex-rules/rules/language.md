# 语言与解释规范

## 默认语言

- 与用户对话：中文。
- `docs/` 文档：简体中文。
- 代码注释：中文为主，标准英文术语、协议名、API 名保持原文。
- 用户可见 UI 文案：简体中文。

## 解释方式

用户熟悉技术语境。引入新概念时先说明它解决什么问题，再说明工程落点。

例如：

- 内容模型：解释为文章、项目、系列、产品服务等内容实体的结构化定义。
- 信息架构：解释为访问者如何理解网站栏目、导航和页面层级。
- 契约词表：解释为跨文档、代码和页面共享的稳定命名集合，用来防止命名漂移。

## 不确定性

禁止臆测用户的想法，不得把用户未明确表达的意图、偏好、优先级、验收标准、业务事实或授权写成既定结论。

对不确定的产品能力、部署方式、第三方服务行为、隐私影响或用户需求，不猜测为事实。能查证的先通过仓库、官方文档或实验查证；查证后仍不确定，或只能由用户取舍时，应明确标记为“待确认”，写清已知事实、可选方案及影响，请用户决策。在获得明确决定前，不得实施依赖该决定的内容。

## 注释

关键内容规则、隐私边界、契约检查和资源路径处理必须写清楚。避免无意义注释。
