# Known Issues

Read only the rows relevant to the task. Historical investigation stays in `docs/progress.md`; this file keeps reusable conclusions only.

| Area | Risk and handling |
| --- | --- |
| Cross-platform line endings | `.gitattributes` is authoritative. Shell scripts and hooks use LF; PowerShell scripts use CRLF. Do not rely on machine-specific `core.autocrlf` settings. |
| Windows PowerShell 5.1 | PowerShell 5.1 may interpret BOM-less UTF-8 through a legacy code page. Keep `.ps1` files as UTF-8 with BOM (`ef bb bf`) and CRLF even when their current prose is English. |
| Duplicate Agent instructions | Translated rules and Skills duplicate instructions in model context and create maintenance drift. Keep Agent and contributor guidance in English only; maintain Chinese pairs only for `README.md`, `SCAFFOLD.md`, and Markdown under `docs/`. `check:localization` rejects Chinese instruction copies. |
| Prompt drift and unnecessary pauses | Repeated workflows can disagree about approvals, tools, or delivery. Keep shared constraints in `AGENTS.md`, route Claude to canonical task rules, and let selected Skills own procedures. Verify commands against project configuration; reuse session authorization and ask only for missing user decisions or permissions. |
| Text scanners | Quality gates scan scripts and documentation, including their own examples. Avoid complete credential shapes and parseable fake secret URLs. An unquoted secret value must end at the line or comment so `token = functionCall(...)` is not misread as a credential. Use an allow marker only after confirming a real false positive. |
| Git hooks | `.githooks/*` must be mode `100755` in the Git index. Test a new hook in a real repository; syntax checks alone do not prove Git invokes it. |
| Archify offline boundary | The upstream template requests Google Fonts, which can stall Chrome `loadEventFired` without network access and creates an undeclared third-party request when a local diagram opens. This repository's vendored template removes remote fonts and disables automatic update checks in the Skill. Reapply `.claude/skills/archify/LOCAL_CHANGES.md` during an upgrade. |
| Archify generated output | Typed JSON and HTML from the pinned renderer support byte-level freshness checks. A Markdown PNG must use the Viewer-native canonical exporter, and its IHDR dimensions must equal viewBox × safe scale. PNG bytes vary with Chrome and the system font stack, so do not compare them across machines. Full-page `visual-check` screenshots are temporary human-review evidence only. |
| PlantUML compilation | Set `PUML_JAR` explicitly and compile under the `SECURE` profile. Every Markdown block owns one following SVG, but SVG bytes are not portable across JAR/JVM/Graphviz/font environments. Gate successful compilation and a non-empty regular artifact; regenerate locally and inspect it instead of imposing byte freshness. |
| Portable document export | Portable HTML under `build/portable-docs/` is ignored output, not editable prose or a source of truth. Pandoc 2.x uses `--self-contained`; 3.x uses `--embed-resources`. The project wrapper selects by version and verifies original image bytes and zero local-resource references before writing. Do not deliver raw Pandoc output around the wrapper. |
| Secret syntax in workflows | Only `${{ secrets.NAME }}` with spaces inside the braces and no surrounding quotes passes the secret scanner. Omitting the spaces or adding quotes is treated as a leak. The generator fixes this syntax; hand-written workflows must preserve it. |
| `gh` write capability | There is no `gh ruleset create`, only check/list/view. Use `gh api --input` for rulesets, branch protection, environments, and Pages. `gh api` exits 1 for both 403 and 404 while writing error JSON to stdout, so parse `.status` instead of relying on the exit code. `gh auth status` can exit 0 after a timeout and is not an authentication verdict. |
| Pushing workflow files | GitHub rejects pushes containing `.github/workflows/*` when the token lacks the `workflow` scope. Run `gh auth refresh -h github.com -s workflow` first; it requires browser authorization. |
| Proving CI is green | `gh run watch` exiting 0 does not prove success: `startup_failure` can evade failure filters, while all-skipped, cancelled, and `continue-on-error` paths can look non-failing. Assert `conclusion == "success"` for every job and step, and treat “no run found for SHA” as failure. |
| Generated workflows | Files with the `managed-by` marker are produced by `npm run gen:cicd`; hand edits fail `check:cicd` freshness. Change `docs/contracts/cicd-answers.json` instead. |
| Release Please ownership | `release-please-config.json` is deterministically generated and must not be edited manually. `.release-please-manifest.json` is created only at bootstrap and then updated by Release PRs. The generator may validate package keys and SemVer but must never reset the version. |
| External workflow semantics | Use the official pinned `actionlint` binary and verify its SHA-256. Run both valid and invalid fixtures so the wrapper cannot swallow exit codes. `zizmor` currently requires every action, including official actions, to be pinned by SHA; that conflicts with current project policy, so do not add a non-blocking pseudo-gate until the policy is reconciled. |
| Writing CI/CD output | Declaring a ledger does not grant ownership of existing files. The generator must reject unmanaged same-name files, symlinks, release configs with unproven ownership, and stale managed artifacts. Stage multi-file changes first and restore old bytes on failure. Lost manifest state must be recovered, not reconstructed from bootstrap values. |
| Deployment dry-run switch | A `workflow_dispatch` boolean remains a boolean in the `inputs` context. Use `!inputs.dry_run`, not comparison with the string `"true"`. Every step in a `kind: deploy` workflow must explicitly be a real deployment or safe preparation so an unclassified step cannot bypass the default dry run. |
